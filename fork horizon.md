# ТЗ: форк Horizon с поддержкой сторонних DLL (libmpv)

Nov 11, 2026 · @Oleg

## 1. Цель

Форк Horizon загружает стороннюю нативную библиотеку libmpv в процесс игры и выводит видео на поверхность в мировом пространстве: экран-блок или панель в мире, а не отдельное окно.

В рамках этого ТЗ не требуется отдельное окно mpv и внешний процесс. Они возможны, но не являются целью.

Критерий успеха: видео воспроизводится на поверхности внутри мира, кадр отрисовывается в нужное место, а стоимость кадра измерена и укладывается в бюджет (раздел 4).

## 2. Текущие ограничения Horizon

Все пункты проверены по тексту `docs/native-mods.md` в репозитории `horizon-rust/horizon` (комит на момент клонирования, глубина 1).

- **Сборка из исходников.** Нативный мод — это mixin-бандл, который патчит исходники игры. Игра собирается `cargo build --locked` целиком (строки \~1866–1919).
- **Зависимости тольки из `Cargo.lock`.** Новый registry-крейт нельзя добавить, если его нет в lock. Библиотеки для модов перечислены в `crates/horizon-mod-deps/Cargo.toml`: `mysql`, `redis`, `tungstenite`, `rusty-opus`, `quinn`, `rusqlite`, `yaml-rust2`, `gif`, `snap`. Биндинги libmpv там нет (строки 576–595). Версия с несовпадающим крейтом даёт `E_CRATE_DEPENDENCY`.
- **У крейта мода нет build-скрипта и своего `Cargo.lock`.** Он не может зависеть от пути или git-крейта (строки 571–574).
- **Сторонние DLL не поддержаны.** Документация не описывает ни линковку `.dll`/`.so`, ни поставку библиотек рядом с игрой. Игра импортирует только системные DLL Windows (строка 1885).
- **Windows-толчушка — MinGW.** x64 собирается `x86_64-pc-windows-gnu` с WinLibs GCC 16.2.0 и UCRT (строки 1872–1873).
- **Стадия запуска.** `[[post_build]]` компилируется и запускается на машине игрока (строки 757–774).
- **Нет доступа к текстурам по размеру кадра.** `draw_quad` берёт спрайты только из атласа игры (`<ns>:block/...`, `<ns>:entity/...`).
- **Внутренняя загрузка есть, но закрыта.** Миникарта загружает своё изображение 128×128 в выделенный слот атласа (`docs/extras.md`, строки 87–94). Такой возможности для модов нет.
- **Нативный код без песочницы.** Мод работает с правами пользователя; требуется `--trust-native-code` (строки 19–22, 2112–2115).

Заметка: в исходниках и каталоге хуков не проверено, доступны ли внутренние модули крейта `horizon-client` из хелперов. Это первое, что нужно закрыть на этапе 0 (раздел 6).

## 3. Функциональные требования

| ID | Требование | Приёмка |
| --- | --- | --- |
| F1 | Манифест мода декларирует сторонние библиотеки: имя, версия, SHA-256 файла для каждой платформы. | Лаунчер отклоняет мод при несовпадении хеша. |
| F2 | DLL загружается только из папки версии игры по явному пути, без поиска в PATH и CWD. | Загрузка из другого места не происходит. |
| F3 | FFI-биндинги libmpv: `mpv_create`, `mpv_initialize`, `mpv_set_option_string`, `mpv_command`, `mpv_terminate_destroy`, подгрузка и воспроизведение файла. | Файл из тестового набора играется в тесте без зависания. |
| F4 | Вывод кадров libmpv через render API: OpenGL или software. Статус Vulkan и wgpu в этой версии mpv не проверен. | Кадр получен в буфер и доступен рендереру Horizon. |
| F5 | Кадр выводится на поверхность блок-сущности в мире через динамическую текстуру (новый механизм, аналог слота миникарты). | Видео видно из игровой камеры на стандартном блоке. |
| F6 | Апи для мода: создать поверхность, загрузить файл, play/pause/seek, закрыть. | Мод может управлять воспроизведением из своих хелперов. |
| F7 | Аудио: mpv выводит звук сам через свой аудио-вывод. Вывод звука в микшер игры в этом ТЗ не входит. | Поведение зафиксировано в документации мода. |

Открытый вопрос: допустимы ли внешние видеофайлы и какие из них без сети. Если да — при запуске нужен фильтр и страница настроек.

## 4. Нефункциональные требования

- **Производительность.** Бюджет кадра на поверхность измеряется и фиксируется до начала работ. Цель-заглушка: не более 2 мс CPU на кадр на среднем устройстве, видео 720p 30 fps. Цифры требуют проверки на реальной сборке.
- **Безопасность.** Нативный мод и так без песочницы (docs/native-mods.md, строка 19). Форк должен добавить хеш DLL и подпись сборки, а также запрет любой загрузки DLL из сети на старте.
- **Совместимость.** Целевая платформа — Windows x64. Windows ARM64 и Linux в первую очередь не входят (документация строки 1883–1885 о сторонних .lib не даёт правил для ARM64).
- **Лицензия.** Исходный код Horizon — MIT. libmpv и его зависимости имеют свою лицензию: при сборке с GPL-компонентами форк станет GPL. Требуется юридическая оценка сборки libmpv.
- **Брендинг и сервисы.** Форк не использует client ID Microsoft и бренд Horizon (docs/forking.md, раздел Microsoft sign-in). Версия с пустым входом допустима.
- **Телеметрия.** Форк не отправляет отчёты о сбойх и производительности без согласия игрока (docs/telemetry.md).

## 5. Варианты архитектуры

На схеме рекомендуемый вариант A: libmpv грузится в процесс игры и отдаёт кадры в динамическую текстуру, которую рисует движок.

&#91;embedded content: архитектура: libmpv в процессе игры, кадры в динамическую текстуру\]

- **A. libmpv в процессе игры (рекомендуется).** Полный вывод в мир. Нужны правки движка и лаунчера: F1–F5.
- **B. mpv отдельным процессом.** Линковка не нужна, кадры передаются через общую память. Сложнее синхронизация, и это всё ещё внешний процесс.
- **C. Покадровая анимация из ассетов мода.** Правки движка не нужны, но живого видео нет: `.hnmod` ограничен 512 файлами и 64 МиБ.

## 6. Этапы и критерии приёмки

Этапы идут по порядку: каждый зависит от предыдущего. Сроки не указаны, их оценивает команда после этапа 0.

| Этап | Работы | Критерий приёмки | Зависит от |
| --- | --- | --- | --- |
| 0. Аудит | Прочитать `crates/horizon-client`: хуки рендера, `native_block_entity_draw`, слот миникарты, `native_hooks.rs`. Подтвердить F5 и доступ хелперов к внутренним модулям. | Список точек врезки и подтверждённый вывод по F5 в документе. | Нет |
| 1. Линковка DLL | Манифест объявляет DLL и её SHA-256. Лаунчер копирует DLL в папку версии и проверяет хеш. Линковка через флаги сборки, задаваемые лаунчером. | Тестовый бинарник вызывает `mpv_client_api_version()` и печатает версию. | 0 |
| 2. FFI-обёртка | Крейт `horizon-mpv` в форке: привязки, безопасная обёртка, запуск файла. Крейт добавляется в `Cargo.lock` форка. | Файл из тестового набора воспроизводится без падений в тесте CI. | 1 |
| 3. Render API | `mpv_render_context` с OpenGL или software, перенос кадра в GPU-текстуру для `wgpu`. | Кадр mpv виден в тестовом окне, цвета совпадают с эталоном. | 2 |
| 4. Экран в мире | Динамическая текстура для блок-сущности, `draw_quad` с ней, бюджет обновления. | Видео играет на блоке в мире. Стоимость кадра замерена и укладывается в бюджет из раздела 4. | 3 |
| 5. API для мода | Хелперы F6: создать, загрузить, play/pause/seek, закрыть. Пример мода. Документация `docs/mods.md` обновлена. | Пример мода управляет воспроизведением из игры. | 4 |
| 6. Релиз | Юридическая проверка сборки libmpv. Сборка Windows x64. Проверка, что нет client ID Microsoft и брендинга Horizon. | Юрист подтвердил лицензию, сборка проходит проверку раздела 4. | 5 |

## 7. Риски и открытые вопросы

**Риски**

- **Движок не открывает внутренние модули для хелперов.** Не проверено. Если так, форк делает разметку в коде движка через замены исходников. Проверяется на этапе 0.
- **Лицензия libmpv.** Сборка с GPL-компонентами делает форк GPL. Нужна сборка без GPL-компонентов или согласование с условиями.
- **Производительность.** Кадр из mpv в GPU-текстуру может съесть бюджет кадра. Измерить на этапе 4, до больших инвестиций.
- **Отставание от Horizon.** Миксины и хуки привязаны к версии `NATIVE_HOOKS_API`. Каждое обновление движка требует ребейза форка.
- **Безопасность.** Сторонняя DLL имеет полный доступ к процессу игры. Хеш и запрет загрузки из сети не заменяют проверки автора мода.
- **Smart App Control на Windows.** Запуск собранных бинарников может быть заблокирован до подписи DLL (docs/native-mods.md, строки 1900–1901).

**Открытые вопросы**

- Разрешены ли внешние DLL в публичном релизе форка, или только в сборке для известных модов?
- Откуда берутся видео: локальные файлы, потоки или и те, и другие? От этого зависит набор протоколов и правил доступа.
- Нужен ли звук в микшере игры? Сейчас mpv играет звук сам (F7).
